# 生命周期与敌意输入审计（2026-11-25 第二遍）

> 上一遍查的是「门槛是否对齐」；这一遍查的是**状态与生命周期**：坏档、时钟、重挂载、超大数值、重置。

## 一、方法

脚本 `.qoder/scratch/check-hostile.mjs`：每种输入各开一个全新标签页，注入 localStorage 后启动，记录
`qi` 显示、`.issue-strip`（故障条）、`.errors`、控制台异常数。

## 三、这轮抓到并修掉的两个

### 1. 红字/坏档提示被关进了面板（我上轮改布局引入的回归）

布局重构把「更多信息」整体挪进面板 sheet 后，`.errors`（红字、坏档、撞步）也跟着进去了。
面板默认关闭 → **玩家永远看不到自己的存档坏了**。

修法：右列新增「故障条」`.issue-strip`，任何 `corrupt / errors / stall` 都在首屏露一条摘要，点开面板看全文。

### 2. StrictMode 二次挂载把「存档已损坏」冲掉

React StrictMode 在开发环境会挂载两次：第一次读档发现损坏 → 备份并清槽 → 第二次读到的是干净新档，
`corrupt` 被 `null` 覆盖，提示消失。

修法：模块级 `pendingCorrupt` 记住本次会话的第一次损坏报告；`corrupted = corruptReport(...) ?? pendingCorrupt`。

（生产构建不会双挂，但页面内任何重挂载都会丢提示，所以仍然要修。）

## 四、查过、确认没问题的

| 项 | 结论 |
|---|---|
| 悟道 / 已学功法的 JSON 解析 | 有容错：坏 JSON → 空数组，非数字 → 0 |
| 阵图阵眼越界 | VM 校验 0..4 整数，越界报类型错误而不是崩溃 |
| 重置存档 | 清掉全部 `gongfa:` 键（含 tutorial/insight/learned/dao/best），下次进来是干净新档 + 重新引导 |
| 离线时钟倒退/超前 | `settleOfflineIfAway` 对 < 60 秒返回 null，不产生负收益 |
| 服丹 | 走火中 / 冷却中 / 心魔 <2% / 存量 <2% 阈值 四条前置都拦 |
| 存档双槽 | 主槽坏自动回退备槽，只给灰字提醒；两槽都坏才报红字 |

## 五、已知但本轮不修

1. **多标签页写冲突**：两个标签同开同一存档，后写覆盖先写（无 `storage` 事件同步）。常见取舍，记为已知。
2. **`.issue-strip` 只显示第一条**：多条红字时要开面板看全。
3. 故障条与「面板 · 详情」按钮在右列上下相邻，窄屏下占约 80px；目前没有折叠。
