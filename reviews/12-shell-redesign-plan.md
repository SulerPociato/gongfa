# 框架与视觉重构方案（参照 iOS / Material 3）

> 触发：玩家反馈「一进来信息太多、不知道看哪」。当前首屏同时出现：右列 4 张卡 + 下方横条 5 张卡 + 顶栏 3 个状态。
> 目标：**首屏只回答三个问题**——我还有多少灵力、接下来做什么、按钮在哪。其余按需展开。

## 一、现状诊断（量出来的）

| 区域 | 当前内容 | 问题 |
|---|---|---|
| 顶栏 | logo + 模式 + 倍速 + 设置 | 尚可，但标题占位过大（logo 字号 18） |
| 右列（320px） | 灵力、渡劫、境界/心魔、试炼 | 4 张卡同时在场，视觉权重相同，主次不分 |
| 下方横条（306px） | 曲线、试炼、藏经阁、功法与道具、更多工具、道途、存档、提示 | 5–7 张卡横向排开，**首屏信息密度最高的一块** |
| 画布 | 积木 | 被两块面板夹住，实际可用宽度 1120/1440 |

结论：**不是"信息多"，而是"所有信息同时以同样权重出现"**。iOS 与 M3 的做法都是分层：一层只放一件事，其余进 sheet。

## 二、设计原则（取 iOS 与 M3 的交集）

1. **一层一件事**：首屏 = 一个大数字 + 一句话 + 一个主按钮。
2. **渐进披露**：其余内容进「面板」sheet；sheet 关闭时世界安静。
3. **动效服务于层级**：sheet 从触发点方向进出，其余元素不做无意义呼吸。
4. **状态层**（M3）：按钮 hover 8%、pressed 12%，不用 `filter: brightness`。
5. **形状与层级**（M3）：小圆角 8（按钮）、中 12（卡）、大 20（sheet 顶部）；三层阴影。
6. **iOS 的"大标题"只用在 sheet 内部**，主界面不放大标题——游戏界面不是设置页。
7. **数字用等宽表格数字**（tabular-nums），避免跳动。

## 四、新框架

```
┌──────────────────────────────────────────────┐
│ 顶栏（48px，半透明模糊）  境界 · 状态点 · 面板 │
├───────────────────────────┬──────────────────┤
│                           │                  │
│        画布（吃满）        │  首屏右列（新）   │
│                           │  ① 灵力（大数字） │
│                           │  ② 下一步（一行） │
│                           │  ③ 主按钮（渡劫） │
│                           │  ④ 细状态条       │
│                           │     心魔 ▓▓ 21%   │
│                           │     效率 1.44 /步 │
│                           │                  │
└───────────────────────────┴──────────────────┘
                    ↘ 关闭 / 打开「面板」
```

- **右列只留 4 件**：灵力、下一步、主按钮、细状态条（心魔 + 效率 + 试炼进度三合一，一行高）。
- 曲线、功法与道具、藏经阁、更多工具、道途、存档、红字 → 全部进 **「面板」sheet**。
- **面板入口**：右列底部一个全宽按钮「面板 · 详情」；顶栏右侧一个 icon。桌面向右滑出（side sheet，420px），窄屏向上滑出（bottom sheet，90% 高，圆角 20 顶部）。
- **sheet 内部**用 iOS 的分组列表样式：分组标题（大标题 20）+ 卡片（12 圆角），而不是现在的横向卡片流。

## 五、动效（写死 token，不做炫技）

| 元素 | 动作 | 参数 |
|---|---|---|
| sheet 进入 | 右滑/上滑 + 淡入 | 300ms emphasized |
| 背板 | 淡入 | 200ms standard |
| 按钮按下 | scale 0.98 | 120ms |
| 主按钮就绪 | 一次 1.02 → 1 脉冲 | 400ms |
| 数字变化 | 已有的 roll 动画保留 | — |
| 面板内卡片进场 | 依次 20ms 延迟淡入 | 300ms |

`prefers-reduced-motion` 下全部压到 0.01ms（已有全局规则）。

## 六、三遍对抗性审查

### 第一遍：回归与兼容

| 质疑 | 结论 |
|---|---|
| 教程第 2/5/6 步的目标（`.qi` / `.demon-row` / `.challenge-button`）会不会被藏进 sheet 而找不到？ | **会**。所以教程进入这些步骤时自动打开 sheet 并滚到目标；步骤结束不主动关（避免闪烁），由玩家关或下一次进入其他步骤时再判断。 |
| Blockly 在 sheet 遮挡时尺寸会变吗？ | 画布宽度不变（sheet 是 overlay），但要 `svgResize()`，否则 flyout 可能错位。打开/关闭各调一次。 |
| 现有 624 个测试会不会大面积红？ | 只改呈现层；选择器 `.hud-bottom` / `.curve` / `.demon-row` 必须保留在 DOM 里（sheet 内），测试与教程选择器都不用改。 |
| 存档/状态机有没有被碰？ | 不碰。 |

### 第二遍：可用性

| 质疑 | 结论 |
|---|---|
| 把信息藏起来，玩家找不到怎么办？ | 入口三处：右列全宽按钮（文案带"详情"）、顶栏 icon、快捷键 `Tab`。按钮上还有一个小红点表示"有新内容"（例如首次悟道/预算撞顶）。 |
| 刚关掉 sheet，红字/报错也藏了？ | 红字不进 sheet：任何 `errors/stall` 优先显示在右列细状态条下方（一行，可点开面板）。 |
| 窄屏 sheet 90% 高会不会挡住画布不能拖？ | 窄屏本来画布在上、sheet 从底部滑出覆盖 90%，此时玩家是在看信息而不是拖积木；下拉或点背板关闭。 |
| 关闭 sheet 后焦点在哪？ | 焦点回到触发按钮；Esc 关闭；打开时焦点进入 sheet 第一个可聚焦元素。 |

### 第三遍：工程风险

| 质疑 | 结论 |
|---|---|
| `backdrop-filter` 在 M3 里不推荐大面积使用（性能） | 只有顶栏与 sheet 背板用，模糊半径 12px；画布与卡片不用。 |
| z-index 冲突（tutorial bubble 12 / sheet?） | 层级定为：画布 0 < 面板 40 < 弹窗 60 < tutorial 气泡 70 < toast 80。教程气泡必须永远在 sheet 之上。 |
| 一次性重写 CSS 容易翻车 | 分两步：先加 token 与新右列（旧面板暂留但默认隐藏），验证后再删旧样式；任何时刻可回退。 |
| 如何验收"不塞信息"？ | 用脚本量首屏可见文本块数量：**首屏可见的独立信息块 ≤ 6**（顶栏 3 + 右列 3–4）。当前是 12+。 |

## 七、交付顺序

1. Token + 新右列（灵力/下一步/主按钮/细状态条）
2. 面板 sheet（复用现有卡片组件，DOM 不删）
3. 教程自动开 sheet + svgResize + 焦点管理
4. 动效与状态层
5. 验收脚本：首屏块数 ≤ 6、六步教程全绿、1440/1280/390 三档无遮挡

## 八、实施结果（2026-11-25）

### 改了什么

1. **右列只留 4 件**：灵力（大数字 + 速率 + 步数）、渡劫（主按钮）、心魔条（含服丹）、「面板 · 详情」入口。
2. **其余全部进面板**：境界（存量/灵根/功法谱/考校）、曲线、试炼、藏经阁、功法与道具、更多工具、道途、红字/存档/提示。
3. **面板是覆盖式 sheet**：桌面从右滑出 420px（圆角 20 只在左上），窄屏从底部滑出 88vh（顶部 20 圆角）；背板淡入 200ms，sheet 300ms `cubic-bezier(0.2,0,0,1)`。
4. **教程联动**：第 4 步的目标在面板里 → 自动开面板；第 5/6 步目标在右列 → 自动关面板，避免被 sheet 盖住。
5. **层级**：画布 0 < 面板 40 < 弹窗 60 < 教程 70 < toast 80（教程压住背板，否则「继续」点不到——这个 bug 实际出现过）。

### 验收数字

| 项 | 结果 |
|---|---|
| 首屏信息块 | 4 个（灵力 / 渡劫 / 心魔 / 面板按钮）+ 顶栏 3 个状态，**比改前少 6–8 块** |
| 桌面面板 | `right:0 width:420 top:48`，`translateX(103%) → 0`，`is-open` 生效 |
| 窄屏面板 | 关闭时 top=866（视口外）；打开 top=101、高 743（88vh）、顶部圆角 20px；关闭按钮可用 |
| 教程六步 | 全部可点通；第 4 步气泡落在面板左侧（x 728–1008，面板从 1020 开始） |
| 测试 | 624 全绿 |

### 已知取舍

- 桌面上面板会盖住右列（覆盖式 side sheet 的必然结果），关闭后恢复；Esc 可关。
- 面板内的卡片仍是旧样式（横条时代的并列卡），下一步可统一成 iOS 分组列表（大标题 + 圆角分组），本轮不做以免一次改太多。
