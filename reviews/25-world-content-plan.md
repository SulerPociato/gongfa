# 修仙资产扩充 · 实施文档（2026-11-26 晚·第二批）

> 需求：用「练气→渡劫 + 仙界」的境界体系、三界七域、宗门、丹药/法宝/阵法/灵根，扩充现有资产；
> 每项都要有**现实算法 / 计算机对照**；功法书越多越好，高级也行。
> 流程：产品 / 开发 / 用户三视角 → 多轮对抗性评审 → 开发 → 全量测试 → 推送。

---

## 一、资深产品经理视角

### 1. 先划一条线：哪些是「资产」，哪些是「平衡」

| 资产 | 本轮做不做 | 理由 |
|---|---|---|
| 9 大境界 + 仙界 5 级 | **做图鉴，不做新可玩境界** | GameState.schema 的 realm 是 0..3，阈值/倍率/目标表按 4 境冻结；赛前加 5 境要改 schema+重跑 11:09 目标，风险远大于收益 |
| 三界七域 | **做世界观图鉴** | 纯内容，直接扩世界观 |
| 宗门/势力 | **做图鉴 + 现实对照** | 同上；给玩家「这个世界有谁」的答案 |
| 丹药/法宝 | **做图鉴（标注背景）** | 本作可服丹只有一枚；其余作为世界观与后续版本接口，不假装能用 |
| 灵根 | **图鉴 + 现有 3 种可玩** | 改灵根分布会动心魔曲线，赛前不动数值 |
| 阵法 | **新增 4 套高级预设** | 现有合并器已支持，只加数据 |
| 功法书 | **5 → 18 套** | 核心诉求；高级书用「图案门槛 + 免费」而不是继续加价 |

### 2. 关键设计：高级功法不收悟道，收「领悟」

上一轮刚把「悟道不够」修好（总价 16 / 来源 17）。如果 10 本新书每本 2–3 悟道，总价会到 40+，又会回到「学不完」。
所以：

- **基础 8 套**：仍花悟道（总价 16），保证经济系统有意义。
- **天阶 10 套**：**0 悟道**，但要求**先领悟指定算法图案**（如「分批吐纳」要 `batch`，「分治」要 `nested`）。
  - 玩家用「搭出来」换「学得到」，和游戏主题（算法）一致；
  - 不增加悟道总价，不会重现「学不完」；
  - 图鉴/按钮直接写「需先领悟：分批吐纳 / 阵图」。

### 3. 新增内容清单

- **功法 10 套**（天阶，免费 + 图案门槛）：
  二分吐纳、缓存预热、流水线、熔断诀、退避重试、限流器、事件循环、分治周天、归并吐纳、布隆过滤。
- **阵法 4 套**（元婴，免费）：玄天剑阵、十二凶煞阵、四灵群妖阵、天罡锁灵阵。
- **世界观图鉴**：9 境 + 仙界 5 级、10 个界域、9 个宗门、8 种丹药、3 件法宝、6 种灵根；每条都有「现实对照」。
- **文案**：图鉴入口放在设置抽屉，默认折叠；不占首屏。

### 4. 成功标准

- 玩家能在图鉴里查到「练气到渡劫」的完整阶梯，并看到每一境对应的计算机概念。
- 藏经阁 18 套，天阶 10 套全部可通过「领悟图案」免费参悟。
- 阵法阁 8 套，全部只追加不替换。
- 不改变任何阈值/倍率/目标表。

## 二、资深游戏开发视角

### 1. 数据层

`apps/web/src/game/world.ts`（纯数据）：

```ts
export interface CodexEntry {
  readonly id: string;
  readonly name: string;
  /** 一句话设定（原创，不抄检索原文）。 */
  readonly note: string;
  /** 现实算法 / 计算机对照。 */
  readonly analog: string;
  /** 是否本作可玩（境界/灵根用）。 */
  readonly playable?: boolean;
}
export const REALM_LADDER: readonly CodexEntry[];   // 9 + 5
export const DOMAINS: readonly CodexEntry[];       // 10
export const SECTS: readonly CodexEntry[];         // 9
export const PILLS: readonly CodexEntry[];         // 8
export const TREASURES: readonly CodexEntry[];     // 3
export const ROOTS: readonly CodexEntry[];         // 6
```

- 内容原创，不复述检索文本；每条 `analog` 是一句 CS 对照。
- `REALM_LADDER` 前 4 条 `playable: true`，其余 `playable: false` 并标注「飞升之后 / 世界观」。

### 2. 功法数据

`scriptures.ts` 扩展：

```ts
export interface Scripture {
  ...
  /** 天阶功法：0 悟道，但要先领悟这些图案。 */
  readonly requires?: readonly PatternId[];
  readonly tier?: 'basic' | 'advanced';
}
```

- `canLearn(scripture, insight, learned, realmIndex, foundPatterns)` 多一个参数。
- `missingPatterns(scripture, foundPatterns)` 返回还缺哪些图案（UI 显示名字）。
- 10 套模板只用现有积木，`compileWorkspace` 必须通过；每套 `requires` 用真实图案 id。
- 成本仍非降序排列基础 8 套；天阶 10 套放最后、cost 0，UI 用 `tier` 分组。
- 现有单测的「成本递增」改成「基础段非降序 + 天阶全 0」，并新增「天阶模板编译」「缺图案不能学」。

### 3. 阵法数据

`formations.ts` 加 4 套 `realm: 3`：
- 玄天剑阵：循环 3 × 引灵 4 眼
- 十二凶煞阵：沙漏包 3 块引灵 3 眼
- 四灵群妖阵：循环 4 ×（引灵 2 眼 + 调息）
- 天罡锁灵阵：引灵 3 眼 + 调息 + 引灵 3 眼
全部免费、只追加；合并器不改。

### 4. UI

- `WorldCodex.tsx`：设置抽屉里的「世界观图鉴」，分组渲染 `REALM_LADDER / DOMAINS / SECTS / PILLS / TREASURES / ROOTS`；
  每行 `名称 · 设定`，下一行 `现实对照：…`；`playable` 用青点标记。
- 藏经阁行增加 `tier` 分组标题「上乘功法 / 天阶功法」；按钮文案：
  - 天阶未满足：`需先领悟：分批吐纳、阵图`
  - 天阶满足：`参悟（免费）`
  - 基础照旧 `学习（N 悟道）`
- 阵法阁 8 行，滚动可达。

### 5. 兼容/风险

- 不动 GameState/schema/阈值/倍率。
- `ScriptureRow` 加 `tier`/`requiresText`；`ScripturePanel` 按 tier 分组。
- 现有 E2E 选择器 `.scripture-learn` 不变；新增行不破坏。
- 图鉴纯展示，不影响游戏循环。

6. 所有原有流程（引导/承雷/存档/手机）不受影响。

## 四、对抗性评审

### 第一遍：经济与门槛

| 质疑 | 结论 |
|---|---|
| 天阶免费会不会让悟道失去意义？ | 基础 8 套仍要 16 悟道；天阶用「图案」作为另一种货币，且图案本身给 +0.5% 产出，仍有价值 |
| 图案门槛会不会卡死？ | 每个天阶只需 1–2 个图案；图案可通过搭积木/炼器炉/藏经阁基础功法发现；图鉴写清缺哪个 |
| 18 套会不会让「学完全部」再次不可能？ | 天阶 0 悟道，只要图案；基础总价仍是 16，来源 17 |
| 高级书模板会不会把图案「白送」？ | 学习只写 learned，不自动抄录；抄录才编译，图案靠玩家自己搭 |
| 成本排序测试会不会红？ | 改测试：基础段非降序、天阶全 0；总价仍 16 |

### 第二遍：世界观与真实性

| 质疑 | 结论 |
|---|---|
| 直接抄检索文本有版权/质量风险 | 只取「境界名/界域名/宗门名」等通用设定，描述全部重写；不复制长段原文 |
| 9 境但只玩 4 境，会不会像半成品？ | 图鉴明确标「本作可玩到元婴；化神以上为世界观与后续版本」，不假装可玩 |
| 丹药/法宝不能真用，会不会误导？ | 图鉴标题写「背景图谱」；可服丹仍只有一枚，避免玩家找不存在的按钮 |
| 灵根 6 种但只有 3 种可玩？ | 图鉴标「本作命格 3 种；五行/变异/天灵根为世界观」 |
| 宗门/界域对玩法没影响？ | 纯世界观资产，满足「扩充设定」；不承诺玩法 |

### 第三遍：工程/回归

| 质疑 | 结论 |
|---|---|
| `canLearn` 多一个参数会不会漏改？ | 全仓只有 App + 单测调用；typecheck 会抓 |
| 18 行藏经阁会不会撑爆面板？ | 面板可滚动；分组标题；390 档截图核对 |
| 天阶按钮文案过长？ | 只显示缺的图案名，最多 2 个；CSS 允许换行 |
| 图鉴长文本会不会卡？ | 纯静态 DOM，默认折叠；不参与帧循环 |
| 新增 4 阵法是否破坏「不替换」？ | 复用同一 mergeFormation；单测遍历 8 套 |
| 原有测试/选择器？ | `.scripture-learn`/`.formation-trace` 保留；新增 `.tier-title`/`.codex-*` |

## 五、开发顺序

1. `world.ts` 数据 + 单测（数量、id 唯一、analog 非空、前 4 境 playable）。
2. `WorldCodex.tsx` + 设置抽屉入口 + CSS。
3. `scriptures.ts` 10 套天阶 + `requires` + `canLearn`/UI。
4. `formations.ts` 4 套高级 + 单测。
5. 全量 typecheck/test/fuzz/build，E2E：图鉴、天阶门槛、阵法 8 套、原有引导/承雷。
6. 推送、线上验证、更新 HANDOFF/契约。
