## 六、三遍对抗性审查

### 第一遍：这些测试会不会给我假绿？

| 质疑 | 结论 / 处置 |
|---|---|
| 用 `element.click()` 会绕过遮挡，遮挡也能「通过」。 | 一律走 CDP 真实鼠标事件 + `elementFromPoint` 命中检查；命中不落在目标上就记失败。 |
| 只读 DOM 文本，不读运行时状态，UI 可以写死假数字。 | 每个数值断言同时读 `window.__gongfa_debug.state()` 与 DOM，两者不一致即失败。 |
| 直接注入 localStorage 存档，绕过了「新档 → 自动存档 → 刷新」的真实路径。 | 拖拽/离线场景用注入；引导/持久化场景用真实操作 + 真实自动存档（S2/S3/S10）。 |
| dev server 有 StrictMode 双挂载，生产没有；在 dev 上测出的问题可能生产不存在，反之亦然。 | Q3 同时在 dev 与 **production preview**（4173）复跑；Q3 的修法在两边都成立。 |
| 计时断言（2s/5s/8s/10s）在慢机器上会 flake。 | 采样留 ≥250ms 余量；关键结论（命中数、结算 rate）用运行时状态而非单帧 DOM；每场景只允许一次重试。 |
| 拖拽用合成 PointerEvent 可能根本没触发 Blockly 手势。 | 已实测：桌面拖拽合成不可靠。**不把「拖拽失败」记为产品缺陷**；改用移动端 palette（真实按钮路径）+ workspace JSON 断言覆盖「加块」；桌面拖拽只做几何/编译单测与手工路径说明。 |
| 只测 1440 与 390，漏了 1280×720 / 平板。 | 本轮至少补 1280×720 的首屏主 CTA/面板矩形；平板记入未测清单。 |
| 单测 632 全绿会让人以为覆盖足够。 | 本轮新增用例只钉住**这次修的纯函数**与契约常量；不宣称覆盖率提升（无 coverage 工具）。 |
