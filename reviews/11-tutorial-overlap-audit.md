# 教程遮挡与"结束后不知道做什么"审计（2026-11-24）

> 方法：脚本按真实路径点完六步，每步同时**截图**和**量相交**（气泡/引导条 vs 每条卡片）。
> 脚本：`.qoder/scratch/audit-tutorial.mjs`（不入库）。

## 一、量出来的事实

1440×900：

| 步 | 气泡与哪些卡片相交 | 引导条与哪些卡片相交 |
|---|---|---|
| 1 | 无 | curve / scriptures / book-artifacts |
| 2 | qi-card | 同上 |
| 3 | 无 | 同上 |
| 4 | 无 | 同上 |
| 5 | **hud-tools / save / realm** | 同上 |
| 6 | **challenge / realm** | 同上 |
| 结束 | — | 同上 |

1280×720 更糟：第 5、6 步的气泡还压到 `book-artifacts / hud-tools`。

结论三条：

1. **底部引导条永远压在下方横条上**（所有步骤）：它固定在视口底部，而横条也在视口底部。
2. **右列目标（心魔条、可渡劫按钮）的气泡被放进右列内部**，于是盖住同列其他卡片（实测第 5 步盖掉「灵根 / 考校 / 功法谱」三行）。
3. **结束后没有去处**：引导条只留 8 秒一句「从这里开始，自己试」，右列「这一步做什么」字号小、位置低，玩家看不到；如果玩家一路点「继续」没拖块，画布是空的。

## 二、方案

### 改动 1：引导条上移，且不横贯整行

- `.tutorial-bar` 改为 `position: fixed; left: 16px; bottom: calc(var(--bottom-height) + 12px)`，宽度 `max-content`（不再 100%），减少遮挡面积。
- 窄屏（≤899px）：改为 `position: fixed; bottom: 8px`（页面底部），因为横条在窄屏是竖向堆叠、不与画布同屏。

### 改动 2：气泡落点分级（按目标所在区域）

`placeBubble` 增加两个边界参数：

- `stripTop`（下方横条顶边）：目标在横条里 → **只允许 above**，且气泡底边 clamp 到 `stripTop - 8`，绝不进入横条。
- `rightColumnLeft`（右列左边界）：目标在右列 → **优先 left**（气泡落进画布），放不下才 above；不再把气泡塞进右列。

放不下的兜底：返回 null → 气泡隐藏，退回引导条（引导条已带「继续」，不会卡死）。

### 改动 3：结束后给"起步卡"（coach）

- 触发：引导结束 **且** 画布上没有动作块（一路点继续的玩家）。
- 位置：画布左下角（不挡工具箱、不挡横条），一行字 + 一个按钮。
- 文案：`① 把「吐纳」拖进「每 tick」` → 拖进第一块后自动变 `② 用「循环」包住吐纳` → 有程序后消失。
- 关闭：按钮「我自己来」，或程序产出 > 0 自动消失，记忆在会话内（不写存档）。
- 结束态的引导条不再显示（避免与 coach 叠）。

## 三、三遍对抗性审查

### 第一遍：范围与一致性

| 质疑 | 结论 |
|---|---|
| 会不会顺手改了教程状态机？ | 不改。步进仍是「点击继续」，只改定位与呈现。 |
| coach 与「这一步做什么」卡片重复？ | 重复但层级不同：卡片是常驻清单，coach 是"你现在该做的第一件事"。程序产出后 coach 消失，只剩卡片。 |
| 移动端引导条会不会又遮挡？ | 窄屏横条是竖向堆叠，引导条固定视口底部仍会盖住页面内容，但只占 35px 且引导期间才有；判定可接受，记入已知缺口。 |

### 第二遍：机制正确性

| 质疑 | 结论 |
|---|---|
| 气泡 clamp 到 `stripTop` 后，目标特别靠上时会不会把气泡顶出视口？ | 会。兜底：clamp 后若顶部 < 8px，返回 null（退回引导条），不硬贴。 |
| 右列目标改走 left 后，箭头还指得准吗？ | 箭头按目标中心投影，左右侧都支持；现有 `arrowCross` 逻辑不改。 |
| 引导条宽度改 max-content 后，长文案会撑多宽？ | `max-width: 560px`，超出换行；1280 下实测文案最长 53 字，两行内。 |
| coach 在「有程序但没产出」时会不会提前消失？ | 消失条件用 `rate > 0`（真产出），不是「有块」。编译失败的块不会让它消失——那正是需要提示的时候。 |

### 第三遍：工程风险

| 质疑 | 结论 |
|---|---|
| coach 会不会挡住 Blockly 的拖拽落点？ | 放画布左下角，宽度 ≤ 320px；Blockly 的放置区在中间。且 coach 仅在"画布无动作块"时出现，此时玩家本就要往「每 tick」拖。 |
| 引导条上移后挡画布？ | 挡画布底部一条 35px，可接受（画布内容在上半部）。比压住横条卡片好。 |
| 结束态 bar 隐藏会不会让"跳过引导"也没了？ | 结束态本来就没有可跳的；跳过按钮只在 step !== null 时渲染，不变。 |
| 新增 DOM 会不会影响命中测试？ | coach 与 bar 都有 `pointer-events: none` 容器 + 按钮 `auto`，不吞拖拽。 |

## 四、验收标准（改完必须全绿）

1. `audit-tutorial.mjs`：六步 `barHits` 全空；第 5/6 步 `bubbleHits` 不含 `realm` / `challenge` / `book-artifacts`。
2. 六步仍能点击翻页（命中测试，不是 `.click()`）。
3. 结束后（空画布）：coach 出现且文案为 ①；拖入吐纳后变 ②；有产出后消失。
4. 1280×720 与 1440×900 都满足 1–3。

## 五、改完的实测（验收标准逐条）

用同一支审计脚本复跑 1440×900 与 1280×720：

```
1440×900：六步 bubbleHits 全 []，barHits 全 []
1280×720：六步 bubbleHits 全 []，barHits 全 []
```

第 5/6 步的气泡现在落在画布内（`x=828…1108`，右列从 1120 开始），不再压住境界/渡劫卡；
第 4 步气泡停在横条上方（`y=510…582`，横条顶 607），不进入卡片区。

起步卡（三种状态实测）：

| 画布状态 | 文案 |
|---|---|
| 无动作块 | ① 把「吐纳」拖进「每 tick」下面的凹槽 |
| 有吐纳、无循环 | ② 用「循环」包住吐纳：次数改成一个数字，产出同样涨 |
| 有循环、未达阈值 | ③ 攒到 1000 就点「可渡劫」 |

说明：判据用「动作块数量」而不是 `rate > 0` —— 境界被动会让 rate 恒大于 0，
用 rate 判会让空画布永远不显示起步卡（第一版就是这么错的，实测抓到）。

## 七、第二轮（实拍反馈后补修）

用户截图暴露出三个第一轮没覆盖的问题：

| 现象 | 根因 | 修法 |
|---|---|---|
| 气泡里的字发灰、读不出来 | 气泡底色用的是 `var(--glass)`（很透），字压在深色画布上等于低对比 | 底色改 `rgba(8,14,18,0.96)`、边框 0.55、字色 `#e9f6f3` |
| 第 4 步气泡与底部引导条叠在一起 | 气泡贴横条上方（y 510–582），引导条也在左下（y 546–582） | 引导条在「气泡已贴住」时移到顶栏下方居中（y 58），只有气泡贴不上时才回左下 |
| 起步卡压住「同样的时间，你的产出提高了 80%」toast | 起步卡在画布内 absolute（bottom 84），toast 在视口 fixed（bottom = 横条 + 16），两套坐标系 | 起步卡改 fixed，和 toast/算法卡共用左下堆叠：toast +16、起步卡 +76、算法卡 +132 |

复测（1440×900 / 1280×720）：六步 `bubbleHits`、`barHits` 仍全空；`bubbleBg = rgba(8,14,18,0.96)`、`color = rgb(233,246,243)`；引导条 `y=58`（顶部居中），与任何气泡都不同带。
