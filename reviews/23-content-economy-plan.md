# 悟道经济、阵法预设与模板扩充 · 实施文档（2026-11-26 晚）

> 玩家原话拆成四件事：
> 1. 悟道只能靠渡劫失败拿，一帆风顺就学不完功法；
> 2. 阵法/道具「只是能找到」，不会用；
> 3. 算法模板、预设功法太少；
> 4. 阵法要有预设，能**叠加**在现有功法上；拓印阵法**不要替换**现有引灵积木。
>
> 本文先分别以**资深产品经理 / 资深游戏开发 / 用户**三视角写清，再做三遍对抗性评审；评审通过后才动代码。

---

## 一、资深产品经理视角

### 1. 问题不是「数值不够」，是三条经济/教学断点

| 断点 | 现象 | 后果 |
|---|---|---|
| 悟道单入口 | 只有渡劫失败 +1 | 顺利玩家 0 悟道；藏经阁整页灰，长期目标消失 |
| 阵法无教学 | 引灵/阵图只在工具箱里「能找到」 | 玩家不会组合，金丹新积木变成负担 |
| 模板太少 | 5 套功法、0 套阵法预设 | 「学功法」一次就见底，没有继续研究的理由 |

### 2. 目标（可验收）

- **顺利玩家也能学完全部功法**：不依赖失败，靠「发现图案」「本境试炼」两条确定性来源。
- **阵法 30 秒内能用上**：一个入口（阵法阁）、一次点击、一条「不覆盖」承诺。
- **模板翻倍**：功法 5 → 8，阵法预设 0 → 4。
- **不破坏现有平衡**：产出倍率、境界阈值、目标表一个都不动。

### 3. 非目标

- 不加抽卡/日常/体力；不做阵法局内编辑器的重写；不改 Blockly 渲染。
- 不把道具改成主动技能；道具仍是常驻装备。

### 4. 经济账（先算再设计）

- 现有功法总价：1 + 1 + 2 + 3 + 5 = **12 悟道**。
- 新增 3 套：静心诀 1、三才引灵 1、分批吐纳 2 → 总价 **16**。
- 新增来源上限：
  - 13 种图案 × 首次发现 +1 = **13**
  - 4 个境界 × 试炼首次达成 +1 = **4**
  - 合计 **17**（不含渡劫失败）
- 结论：**即使一次都不失败，集齐图案 + 试炼也能学完全部 16 点功法，余 1 点**。失败仍是加速器，不再是门票。
- 阵法预设 **免费**（只受境界门控），因为它是「怎么用」的教学，不是第二套货币。

### 5. 优先级

P0：悟道来源 + 阵法阁叠加 + 不替换保证 + 新模板。
P1：阵法首次提示、道具「什么时候用」常显、补发提示。
P2：阵法拓印后的速率对比、更多图案（不做）。

## 二、资深游戏开发视角

### 1. 悟道来源（元进度，不动 GameState）

新增 `apps/web/src/game/insightSources.ts`：

```ts
export const PATTERN_INSIGHT = 1;
export const TRIAL_INSIGHT = 1;
export function patternSource(id: string): string;   // 'pattern:linear'
export function trialSource(realm: number): string;  // 'trial:2'
export function sourceIds(found: readonly string[], trialRealms: readonly number[]): string[];
export function missingSources(all: readonly string[], awarded: readonly string[]): string[];
```

- `gongfa:insight` 仍是余额（现有键）。
- 新增 `gongfa:insight:awarded`：已发过的来源 id 数组，**去重账本**。
- `insightStore.ts` 增 `readAwarded / writeAwarded`；坏 JSON 回空、不抛。
- 发放点：
  1. `recognizePatterns()` 里 `fresh` 每个 `pattern:<id>` 发 1；toast 末尾加「· 悟道 +1」。
  2. 帧循环 `state.sprintReached && !prevSprintReached` 时 `trial:<realmIndex>` 发 1。
  3. 启动补发：扫 `readFound` + `gongfa:best` 的境界键，缺的发；通知「补发悟道 +N」。
- 账本先写、余额后写；余额写失败时下次启动会按账本差集补，不会重复发。
- 只发一次：同一图案第二次发现不会再加；换档不重复（账本全局，与 insight 同）。

### 2. 新功法（3 套，插在成本升序的位置）

| id | 名称 | 成本 | 境界 | 形态 |
|---|---|---|---|---|
| `jingXin` | 静心诀 | 1 | 筑基 | 循环 5 次：先调息再吐纳 |
| `array3` | 三才引灵 | 1 | 金丹 | 引灵 + 阵图 3 眼 |
| `batch` | 分批吐纳 | 2 | 金丹 | 沙漏包 3 次吐纳 |

- 总成本 16；`SCRIPTURES` 保持成本非降序（现有单测会查）。
- 每套都要过 `compileWorkspace`（现有单测自动覆盖）与 `missingBlocks` 闸。

### 3. 阵法阁（免费预设 + 合并，不替换）

新增 `apps/web/src/game/formations.ts`：

```ts
export interface FormationPreset {
  id; name; algorithm; teach; realm; realmName;
  build: () => Record<string, unknown>; // 要追加的块链（含唯一 id 占位）
}
export const FORMATIONS: readonly FormationPreset[];
export interface MergeResult { workspace: unknown; appended: number; kept: number; arraysBefore: number; arraysAfter: number; }
export function mergeFormation(current: unknown, preset: FormationPreset): MergeResult;
```

合并规则（这是玩家点名要求的核心）：

1. 深拷贝当前 workspace；不改原对象。
2. 找 `tick_hat`；没有就建一个（不常见，但坏档/空画布要能接）。
3. 沿 `hat.inputs.BODY.block.next` 走到链尾，把阵法块链接在 `next` 上；BODY 空则直接放进 BODY。
4. **只新增块**：现有块（尤其 `gongfa_array` 引灵）原样保留，不删除、不改写、不替换。
5. 新块 id 用 `form-<preset>-<n>` 并与现有 id 去重。
6. 返回 `arraysBefore/arraysAfter`，UI 用它在确认框里说「原有 X 块引灵，追加后 Y 块」。

预设 4 套（全部免费，境界门控）：

| id | 名称 | 追加内容 |
|---|---|---|
| `threeTalents` | 三才引灵阵 | 引灵 + 阵图 3 眼 |
| `zhouTianArray` | 周天引灵阵 | 循环 5 次：引灵 + 阵图 2 眼 |
| `fourSymbols` | 四象护体阵 | 引灵 4 眼 + 调息 |
| `microBatch` | 微批引灵阵 | 沙漏包：引灵 2 眼 ×2（重置边际递减） |

- 拓印入口：面板「阵法阁」每行一个「拓印到现有功法」。
- 确认框写明：**只在末尾追加；不替换你已有的引灵积木**；显示 `kept` 与 `arraysBefore→arraysAfter`。
- 拓印前后各取一次速率，3 秒后 toast 对比（复用抄录功法的逻辑）。
- 境界不够显示「金丹解锁」；积木当前境界给不出时拒绝（复用 `missingBlocksIn`）。

### 4. 教学

- 金丹首次进入：一次性 moment「引灵/阵图怎么用」，文案含 2 眼 +26%、3 步/次、阵法阁入口。
- 道具面板：每件未锁定的都常显「什么时候用」（原来只在装备后显示）；顶部加一句区分「道具是常驻效果，阵法是积木」。
- 藏经阁提示改成三行来源，并显示已发现图案数 / 已达成试炼数。

### 5. 兼容与数据

- 不动 GameState/schema；不动产出/阈值/目标表。
- 老玩家：启动补发按 `found` + `best` 差集；账本缺失时一次性补齐。
- 清档：`resetAllSaves` 的 `gongfa:` 前缀覆盖新键。
- 契约：§4.9 加「首次发现 +1 悟道」；§4.12 更新功法表与来源；新增 §4.13 阵法阁；§9 加账本键。

## 三、用户视角（验收脚本）

1. **我一帆风顺**
   - 我从不渡劫失败，只靠发现图案和打试炼。
   - 每发现一种新写法，toast 说「刚发现… · 悟道 +1」；藏经阁余额增加。
   - 每境试炼达成，悟道 +1。
   - 集齐 13 图案 + 4 试炼后，我能学完全部 8 套功法（总价 16，我至少有 17）。
2. **我不会用阵法**
   - 我进金丹，看到一条提示：「引灵拖进功法，再把阵图拖进它的阵位；2 眼 +26% 产出、3 步/次；也可去阵法阁一键追加」。
   - 我打开面板 → 阵法阁，点「拓印到现有功法」，确认框告诉我「只追加、不替换，原有 2 块引灵保留」。
   - 点确认后，我原来的引灵还在，末尾多了新的阵；速率对比 3 秒后弹出来。
3. **我道具不会用**
   - 道具面板每件都有一句「什么时候用」，不用先装备才看得到。
   - 顶部写明「道具装上就生效；阵法是积木，要去阵法阁或自己拖」。
4. **模板太少**
   - 藏经阁从 5 套变 8 套；阵法阁 4 套预设；都能一键落到画布。

## 四、对抗性评审

### 第一遍：经济与「刷悟道」

| 质疑 | 结论 / 处置 |
|---|---|
| 图案发现可以反复刷吗？ | `found` 去重 + `gongfa:insight:awarded` 账本双保险；同一图案只发一次 |
| 换档/清档能重复领吗？ | 账本是全局元进度（与 insight 同），清档按 `gongfa:` 前缀一起清；换档不重复 |
| 13+4=17 真够吗？如果玩家只发现 10 种图案、0 试炼？ | 够不着 16 是设计内的「继续研究」；失败仍 +1，且 8 套里最贵 5 点，不是必须全买 |
| 补发会不会给老玩家白送一大笔？ | 按已发现图案/已达成试炼补，本来就是他们挣过的；上限 17 |
| 新功法定价会不会破坏「成本递增」测试？ | 插在非降序位置，总价 16；单测覆盖 |
| 悟道余额写失败、账本写成功怎么办？ | 余额少发，下次启动差集补；不会重复发 |
| 试炼 `best` 表能代表「达成过」吗？ | 只有达成时才写 best（App 帧内），可代表；坏表回空，最多少补 |

### 第二遍：合并语义（不替换现有引灵）

| 质疑 | 结论 / 处置 |
|---|---|
| 追加到 BODY 链尾会不会改到现有块？ | 只给链尾写 `next`，其余块不碰；单测深比较原引灵块 JSON |
| 现有 BODY 为空 / 没有 hat？ | 空则直接塞 BODY；无 hat 建一个；都有测试 |
| 链尾是循环/条件块，能接 next 吗？ | 都是语句块，有 nextStatement；接在循环之后 = 循环跑完再放阵，语义明确 |
| 会不会把玩家原有引灵「覆盖」？ | 不会：merger 不遍历/不删除 array 块；确认框显示 before→after |
| 追加的块 id 冲突？ | 扫描现有 id，生成不重复的 `form-*` |
| 拓印后 compile 失败怎么办？ | 复用 `reloadCanvas` 的编译降级路径；确认前先 `missingBlocksIn` 检查积木可用 |
| 阵法是「叠加」还是「另起一段」？ | 追加到现有功法末尾，同 tick 都执行；不是全局 buff，不改变已有引灵的 runes |
| 免费阵法会不会让付费功法贬值？ | 阵法是 4 个固定形态，功法是 8 套算法教学；免费降低「不会用」的门槛 |

### 第三遍：工程/回归

| 质疑 | 结论 / 处置 |
|---|---|
| 加 3 套功法会不会撑爆面板？ | 面板可滚动；单行高度不变；390 档截图核对 |
| 阵法阁会不会让面板太长？ | 放在藏经阁之后，4 行；滚动可达 |
| 新增 moment 会不会重复弹？ | 走现有 `PERSISTED_MOMENTS`/seen 机制，一次性 |
| `recognizePatterns` 里发悟道会不会递归/重复？ | 只在 `fresh` 分支发，账本去重；`refreshScriptures` 不触发识别 |
| 补发在 StrictMode 双挂载会双发吗？ | 账本先写；第二次挂载读到已发，差集为空 |
| 改契约算「改冻结数值」吗？ | 只加来源/内容，不改阈值、倍率、目标表；§3 表不动 |
| 测试范围？ | insightSources 纯函数、formations 合并、新功法编译、总价上限、E2E 补发/拓印/不替换 |
| 回退？ | 悟道来源/阵法师独立模块；新功法是数据；关掉入口即可回退 |

## 五、开发顺序

1. `insightSources.ts` + `insightStore` 账本 + 单测；
2. 发放/补发接入 App + 藏经阁文案；
3. 3 套新功法 + 单测；
4. `formations.ts` 合并 + 单测；
5. 阵法阁 UI + 拓印流程 + 确认框；
6. 金丹引灵 moment、道具「什么时候用」常显；
7. 全量测试 + E2E（补发、拓印不替换、阵法提示）+ build + 推送。

## 六、验收口径

- 新玩家不失败也能拿到 17 点来源；全部功法总价 16。
- 拓印前后原引灵块 JSON 完全一致，`arraysAfter = arraysBefore + 1`。
- 藏经阁 8 套、阵法阁 4 套，全部可编译。
- typecheck 0、测试全绿、线上 bundle 更新。
