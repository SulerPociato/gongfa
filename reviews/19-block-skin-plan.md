# 积木皮肤与画布国风化方案（2026-11-26 下午）

> 触发：玩家给了一张参考图（深色墨底、云纹、发光描边的积木、竖排单字符瓦、块间细链与圆节点），问「能实现吗，再加点修仙/国风元素」。
> 纪律：大改动先方案 + 三遍对抗性审查，再动代码；不碰数值、不碰存档、不碰 Blockly 的编译/拖拽语义。

## 一、参考图拆解：哪些能照搬，哪些不能

| 参考元素 | 能否 | 做法 / 原因 |
|---|---|---|
| 深色墨底 + 云纹 + 远山 + 雾气 | **能** | 纯 CSS/内联 SVG 背景层，画在 Blockly 主背景之下 |
| 发光描边积木（青/金/朱） | **能** | 主题色 + CSS 覆盖 `.blocklyPath` 的 stroke/fill + drop-shadow |
| 块体透明、只留边 | **能** | `fill: rgba(...)`，隐藏 geras 的高光/阴影两层 path |
| 更圆的角、更小的凹槽 | **能（有风险）** | 自定义 geras 渲染器改 `CORNER_RADIUS / NOTCH_*`；先 CSS 版，渲染器作为第二步并可回退 |
| 竖排单字瓦片（符/灵/凝/心…） | **不能照搬** | Blockly 按横排文本量尺寸；竖排会溢出并撑破块高。改成「左边一枚符字小印 + 横排中文标签」，保住可读性 |
| 块间细链 + 圆节点 | **部分** | 连接线是 Blockly 内部 path，不给挂钩；用「块描边 + 选中脉冲」表达连接感，不硬造 DOM 节点 |
| 朱红内层分支 | **能** | 按块型分色：动作=青、控件=金、条件=朱（参考图内层就是朱红） |

结论：**形似（描边/发光/墨底/云纹/朱青金三色）可以做到；竖排单字瓦片不做**，否则要么改渲染器重写文本布局，要么把标签缩成单字，两者都会伤「玩家看得懂自己写了什么」。这是取舍，不是偷懒。

## 二、视觉方案

### 1. 画布（.canvas 背景，全部在积木之下）

分层（由底到顶）：

1. 墨黑径向渐变（中心偏青、四周更深）+ 顶部渐隐。
2. **法阵环**：内联 SVG，双圈 + 八节点 + 刻度，中心 50% 58%，560px，青色 10% 透明。
3. **祥云**：左下/右上各一组线描云纹，青色 8%。
4. **远山**：底部两层折线山影，墨青 20%。
5. **流雾**：两条慢速漂移的径向渐变（60s/90s），`prefers-reduced-motion` 下静止。
6. 极淡的 48px 点阵（保留坐标感，但不抢戏）。

### 2. 积木（CSS 皮肤，默认 geras 渲染器）

- 隐藏 `.blocklyPathLight / .blocklyPathDark`，只留主 path。
- 按块型类名分色描边：
  - `.gongfa_hat` 青白 `#8ff5e6`，填充 `rgba(8, 26, 28, .88)`
  - `.gongfa_action` 灵气青 `#35e0c8`
  - `.gongfa_control` 符纸金 `#e8c978`
  - `.gongfa_logic` 朱砂 `#ff7b63`（参考图内层朱红）
  - `.gongfa_value` 淡青 `#9fe8dd`
- 描边 1.3px + `drop-shadow(0 0 3px 同色 35%)`；选中 2px + 8px 光晕；hover 轻微提亮。
- 块文字：思源宋体（已有本地字体）+ 字距 0.08em + 米白 `#e9f6f3`；数字/字段用等宽。
- 工具箱（flyout）：深玻璃底 `rgba(8,14,16,.72)` + 右侧 1px 青光 + 阴影；块预览同皮肤。
- 缩放控件：玻璃圆钮 + 金色 hover（现有按钮已接近，只调色）。

### 3. 国风挂件（overlay，`pointer-events:none`，只在画布边缘）

- 左下：**朱印**「道」（38×38，圆角 4，朱砂底、米白字、轻微做旧）。
- 左侧竖排小字：`灵台方寸 · 一念通天`（11px，字距 0.3em，青 35%）。
- 右上：云纹一枚（与背景同族，避免两套画风）。

挂件层 `z-index: 1` 在画布之上、HUD 之下；位置贴边，不压积木主区域。

### 4. 不加的东西

- 不加竖排积木字、不加块间链节点、不加音效、不改布局与 HUD。
- 不改积木 `message0`（教程、图鉴、编译都读它）。

## 四、三遍对抗性审查

### 第一遍：功能回归

| 质疑 | 结论 / 处置 |
|---|---|
| 隐藏 `.blocklyPathLight/Dark` 会不会让选中/禁用状态看不出来？ | 选中改用主 path 的 `stroke-width` + drop-shadow；禁用块 Blockly 用 pattern 覆盖，仍在主 path 上；逐块截图核对 |
| `fill: rgba(...)` 会不会把折叠块、插入标记也改花？ | 选择器只命中 `.blocklyDraggable.gongfa_* > .blocklyPath`；插入标记是 `.blocklyInsertionMarker`，单独保留半透明；折叠块仍走同一 path，颜色一致即可 |
| 自定义渲染器会不会改坏拖拽吸附/几何？ | 第二步才做，且只改圆角/凹槽尺寸；先跑全块型截图 + 拖拽手测；坏了就回退到 CSS 版（commit 单独） |
| 背景层会不会吃掉鼠标事件？ | 背景是 `.canvas` 的 background-image，不产生元素；挂件层 `pointer-events:none`；Blockly SVG 仍是最上层可交互元素 |
| 挂件 `z-index:1` 会不会压住积木？ | 挂件只贴四边，且 `pointer-events:none`；截图核对 1440/390 两档不压主块 |
| 会不会影响教程气泡定位？ | 气泡按目标 `getBoundingClientRect` 算，不依赖背景；六步引导复跑 |
| 会不会影响 E2E 的 `elementFromPoint`？ | 挂件 none 命中；积木描边不改变布局盒子；S5/S8 复跑 |

### 第二遍：可读性与可访问性

| 质疑 | 结论 / 处置 |
|---|---|
| 深底 + 亮描边，文字对比度够吗？ | 文字仍是 `#e9f6f3` on `rgba(8,20,22,.88)`（≈17:1）；新增朱砂描边不承载文字信息 |
| 色盲玩家能分清青/金/朱吗？ | 块型还有形状差异（hat/语句/值/控件）与文字标签，颜色不是唯一编码 |
| 发光会不会糊住文字？ | drop-shadow 只挂在 path 上，不挂 text；选中 8px 光晕也只在边缘 |
| 动效敏感用户？ | 流雾动画在 `prefers-reduced-motion` 下关闭；选中脉冲改为静态描边 |
| 移动端性能？ | 每块一个 drop-shadow，15 块以内；雾动画是 transform，不触发重排；390 档测帧时间 |

### 第三遍：工期与回退

| 质疑 | 结论 / 处置 |
|---|---|
| 截止 11-29，改视觉会不会耽误功能？ | 只动 CSS/主题/一个挂件组件；渲染器是可选第二步。每步可截图验证，失败回退单 commit |
| 参考图是 AI 生成，照抄会不会不伦不类？ | 只取「墨底/云纹/描边/三色」四个抽象特征，不复制具体纹样；配色沿用现有五色 token |
| 会不会把 1.1MB 包再撑大？ | 背景是 CSS 内联 SVG（几 KB），挂件是 DOM，无新依赖 |
| 怎么验收「像」？ | 截图对比：1440 全块型、390 手机、选中/拖拽态；给出改前/改后两张图 |
| 玩家可能不喜欢怎么办？ | 皮肤集中在 CSS 变量与一个 `.gongfa-skin` 作用域，回退只需删一段 CSS；theme 可单独 revert |

## 五、执行顺序

1. 基线截图（`v0-baseline.png`，已拍）。

5. 推送、线上验证、写 `reviews/20-block-skin.md` 记录改前/改后与取舍。
